# KDOps — KD Squares Operations Platform

Internal finance and operations hub for **KD Squares Ltd**, Nigeria.  
Manages payments, payroll, expenses, fleet, compliance, HR, and more — backed by Supabase and processed through Paystack.

---

## Stack

| Layer | Technology |
|---|---|
| Frontend | React 18 + TypeScript + Vite |
| Styling | Tailwind CSS + shadcn/ui |
| Backend / DB | Supabase (PostgreSQL + RLS + Edge Functions) |
| Auth | Supabase Auth (email/password) |
| Payments | Paystack (transfers API via Edge Functions) |
| Error monitoring | Sentry (optional, free tier) |
| Hosting | Vercel |

---

## Local Development

### Prerequisites

- Node.js ≥ 18
- A Supabase project (free tier is fine for dev)
- A Paystack account (test keys for dev)

### Setup

```bash
git clone https://github.com/king-iyene/kd-ops-hub.git
cd kd-ops-hub
npm install
cp .env.example .env.local
# Fill in .env.local — see table below
npm run dev
```

The dev server starts at `http://localhost:5173`.

## Environment Variables

Create `.env.local` (never commit this file):

| Variable | Required | Description |
|---|---|---|
| `VITE_SUPABASE_URL` | ✅ | Your Supabase project URL (`https://xxx.supabase.co`) |
| `VITE_SUPABASE_ANON_KEY` | ✅ | Supabase anon/public key |
| `VITE_PAYSTACK_PUBLIC_KEY` | ✅ | Paystack public key — use `pk_test_` for dev, `pk_live_` in prod |
| `VITE_SENTRY_DSN` | optional | Sentry DSN — leave blank to disable error reporting |

> **Production**: Set these in Vercel → Project → Settings → Environment Variables.  
> Sentry is a no-op when `VITE_SENTRY_DSN` is unset — the app works fine without it.

## Deployment

The app deploys automatically to Vercel on push to `main`.

```bash
# Manual deploy (if needed)
npx vercel --prod
```

Security headers (CSP, HSTS, X-Frame-Options, etc.) are defined in `vercel.json`.

### Supabase Migrations

SQL migrations live in `supabase/migrations/`. They must be applied manually in the Supabase SQL editor (or via the Supabase CLI if configured):

```bash
# If using Supabase CLI
supabase db push
```

## Role System

| Role | Access |
|---|---|
| `super_admin` | Full access, can impersonate other roles via "View As" |
| `admin` | Full operational access |
| `finance` | Payments, payroll, expenses, reports |
| `operations` | Fleet, contractors, tasks |
| `field_staff` | Own expense claims, leave requests, tasks |

Roles are stored in `profiles.role` and enforced via Supabase RLS policies.  
Super admins can switch view via the **View As** banner to test any role's experience.

## Key Conventions

### Payment References

Every Paystack transfer initiated from this platform uses the `kdops_` prefix:

```
kdops_{first 20 chars of UUID without dashes}
```

Generated by `generateKdopsRef(id)` in `src/lib/paystack.ts`. Search for `kdops_` in the Paystack dashboard to identify all platform-originated transfers.

### Dual Approval

Payment batches above the configured threshold require two approvers. The `approved_by` field stores the final approver; the audit log captures the full approval chain.

### Audit Log

Every significant action (payment initiation, approval, rejection, role change, etc.) writes a row to the `audit_logs` table via `logAudit()` in `src/lib/audit.ts`.

## Troubleshooting

**Blank screen / auth loop**: Check that `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` are set correctly.

**Payments not processing**: Ensure Paystack Edge Functions are deployed to Supabase and `VITE_PAYSTACK_PUBLIC_KEY` matches the key the Edge Functions use on the server side.

**Transactions view missing columns**: Run the latest migrations in `supabase/migrations/` — particularly `20260622000000_transactions_view_remove_transfers.sql`.

**Console warning `[KDOps] Paystack test key in production`**: The app detected `pk_test_` in a non-localhost environment. Update `VITE_PAYSTACK_PUBLIC_KEY` to your live key in Vercel environment variables.
