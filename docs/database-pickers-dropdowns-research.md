# Pickers that scale: what KDOps Database should copy

The best database hybrids converge on one picker contract: a popover anchored to the cell with an autofocused search box, a bounded list, a trailing "create" row, and per-selection changes. Their weak points are also shared: names truncated, filters that do not hold for paste or API, paste that merges options, and tab strips that collapse past a few dozen tables. KDOps already has the core pieces (search, linked list, suggestions, remove, open-record, create-and-link, All tables popover, hidden toggle). The highest-value gaps are therefore not new features. They are keyboard and ARIA correctness, search that spans more than the display field, a count-aware overflow chip, a documented create-option rule for selects, and a "N hidden" affordance on the table switcher. Most of this is client-only. Only per-base ordering of tables, option usage counts, and strict link-target limits need database work. Evidence quality is uneven: Airtable, Baserow, NocoDB, Grist and the W3C patterns are verified from official pages. Teable, Monday, ClickUp, SeaTable, Smartsheet and Coda rest mostly on snippets and forum posts, and keyboard behaviour for nearly every product is undocumented, so the keyboard spec below is a W3C-derived recommendation and not a competitor copy.

## Linked-record cells converge on chips, search-first pickers and an inline create row

**Closed cell.** Airtable, Baserow, Notion and Grist show linked records as chips or tokens labelled with the primary (or a chosen "show") field. NocoDB instead shows a count that opens a Linked Records modal ([NocoDB Links docs](https://nocodb.com/docs/product-docs/fields/field-types/links-based/links)). Baserow confirmed that very large link sets overflow its expanded cell, with no fix recorded ([Baserow forum](https://community.baserow.io/t/ui-issues-cell-does-not-display-properly-for-very-large-link-to-table-fields/3261)). No vendor documents a "+N" overflow rule, chip max-width, or row-height behaviour, so KDOps's recent "chips fit the lines of a tall row with a +N" work (commit 551f849c) is already ahead of anything the notes can verify. A per-link display-field override is shipping at NocoDB (2026.05.0, paid tiers) and applies to pills, picker, cards and search ([NocoDB changelog](https://nocodb.com/docs/changelog/2026.05.0)); Airtable has a narrower version that affects only the picker ([Airtable linking records](https://support.airtable.com/docs/linking-records-in-airtable)).

**Picker.** The common baseline across Airtable, Baserow, NocoDB, Grist and SeaTable is search, create-new, open record, unlink, limit-to-view, and a single-versus-multiple toggle. Baserow opens a modal with search, shows 10 rows per page, and offers "+" to create and link ([Baserow docs](https://baserow.io/user-docs/link-to-table-field)). NocoDB offers record cards with an expand icon, multi-link in one pass, and "+ New record" ([NocoDB Links docs](https://nocodb.com/docs/product-docs/fields/field-types/links-based/links)). Grist uses an inline autocomplete with a "+" option that adds the typed value as a new record and inserts the reference in one step ([Grist reference columns](https://support.getgrist.com/col-refs/)). Airtable alone shows a "Top matches" group, and that group is AI-driven with up to 20 suggestions ([Airtable docs](https://support.airtable.com/docs/linking-records-in-airtable)). KDOps's existing "Suggestions" grouping therefore has no documented non-AI competitor equivalent, and I could not verify how it should be ranked.

**What went wrong elsewhere.** Airtable's redesigned Interfaces picker removed the "+" create button so that creation appears only after typing, truncated names to roughly half the previous length, and gave no choice of fields shown; Airtable temporarily rolled it back ([Airtable community](https://community.airtable.com/t5/interface-designer/limitations-with-new-linked-record-picker/m-p/171927)). Airtable users also complained that the legacy picker closes after every selection even on multi-link fields ([Airtable community](https://community.airtable.com/legacy-product-ideas-75/ux-when-populating-a-multi-link-column-don-t-close-editor-41980)). NocoDB regressed picker search to the display column only in 2026.04.0 and restored multi-field search in 2026.05.0 ([NocoDB changelog](https://nocodb.com/docs/changelog/2026.05.0)). View-based limits restrict only the picker and not paste or API in Airtable and NocoDB, and SeaTable's limit also fails for auto-add ([SeaTable forum](https://forum.seatable.io/t/link-to-other-records-limit-row-selection-to-a-view-problem/2673)). The lessons for KDOps are to keep create visible, keep the picker open on multi-link, search more than the primary field, show full names (or a tooltip), and enforce any "allowed targets" rule in the data layer if it must be strict.

**Scale.** NocoDB is the only vendor documenting a scalable picker: virtual scrolling plus a chunked cache that stays responsive with thousands of records ([NocoDB changelog](https://nocodb.com/docs/changelog/2026.05.0)). Baserow made search instant rather than Enter-triggered and tested it on 100k+ row tables ([Baserow MR 945](https://gitlab.com/baserow/baserow/-/merge_requests/945)), yet it still paginates about 10 rows and has said the modal needs a redesign ([Baserow forum](https://community.baserow.io/t/enhancing-navigation-for-large-lists-in-link-to-table-fields/4470)). Monday caps linked items at 10,000 per board ([Monday community](https://community.monday.com/t/connected-items-limit-on-a-board/42080)). Scale behaviour for Airtable, Notion, Teable, Coda, ClickUp and SeaTable is unknown.

## Select editors converge on type-to-filter, a create row and gated option creation

Every product renders options as coloured pills. Palettes range from 15 colours at Baserow ([Baserow single select](https://baserow.io/user-docs/single-select-field)) to 24 at SeaTable and 40-plus at Monday; NocoDB states its hue grid is chosen to be readable in light and dark mode ([NocoDB single select](https://nocodb.com/docs/product-docs/fields/field-types/select-based/single-select)). Grist separates fill and text colour per choice ([Grist column types](https://support.getgrist.com/col-types/)). Notion assigns random colours, while SeaTable and Monday assign by index; ClickUp users complain that colours are forced ([ClickUp feedback](https://feedback.clickup.com/feature-requests/p/ability-to-have-no-color-assigned-to-dropdown-options-by-default)). Index-based rotation is the more defensible default because it is predictable.

The editing flow is consistent. Baserow opens a dropdown on click, filters as you type, and shows "+ Create new option" that adds the option permanently and applies it ([Baserow multiple select](https://baserow.io/user-docs/multiple-select-field)). Grist does the same with an inline menu item ([Grist column types](https://support.getgrist.com/col-types/)). Creation from the cell is permission-gated in three ways: Airtable limits it to Owners and Creators ([Airtable single select](https://support.airtable.com/docs/single-select-field)), Teable has "Allow new options when editing" ([Teable help](https://help.teable.ai/en/basic/field/single-select)), and Smartsheet distinguishes restricted lists from free text, which lands in the cell but not the column's value list ([Smartsheet dropdown help](https://help.smartsheet.com/articles/2480081-dropdown-list-column-type)). A per-field switch is the cleanest answer to option sprawl. Rename and recolour propagate to every row in Baserow, Teable and Grist. Grist is the only vendor documenting chip keyboard handling (arrow keys and Delete move through and remove chips, Enter or Tab saves, Escape discards).

Paste is the industry's weakest area. Airtable merges pasted multi-select values into one option such as "Monday Tuesday Wednesday" ([Airtable community](https://community.airtable.com/other-questions-13/copy-and-paste-multi-select-options-8386)), Coda mis-splits commas ([Coda community](https://connect.superhuman.com/t/importing-select-lists-with-multiple-values/30408)), and Airtable's CSV "create missing options" has been reported to leave records without the new options ([Airtable community](https://community.airtable.com/other-questions-13/importing-a-csv-file-create-missing-select-options-dude-where-s-my-new-options-47802)). In the options editor, ClickUp supports pasting a list one per line up to 500 options ([ClickUp changelog](https://feedback.clickup.com/changelog/paste-options-in-bulk-for-label-dropdown-custom-fields)) and Grist splits multi-line paste into multiple choices; Airtable cannot. Airtable's multi-select filter operators (is exactly, has any of, has all of, has none of, is empty, is not empty) are the best documented model, and empty rows always match "has none of" ([Airtable multiple select](https://support.airtable.com/docs/multiple-select-field)). Airtable cannot group by individual multi-select options. Option limits worth noting: Airtable allows 10,000 options per field ([Airtable multiple select](https://support.airtable.com/docs/multiple-select-field)); Smartsheet users reported a form showing only the first 100 of about 200 values in a restricted list ([Smartsheet community](https://community.smartsheet.com/discussion/98084/only-first-100-values-dropdown-list-in-forms)), which is one old, single report. The field-settings consensus is rows of drag handle, colour, name and delete, with Enter to add, default value, and an optional alphabetise toggle. NocoDB's alphabetise toggle locks manual reorder ([NocoDB multi select](https://nocodb.com/docs/product-docs/fields/field-types/select-based/multi-select)), which is the failure mode to avoid. Delete clears cells in Airtable, Baserow and NocoDB, so a usage count and confirm step is warranted. Airtable's "Show dependencies" is paid-only.

## The table switcher: tabs break at scale, so hide, search and count

Airtable and SeaTable use a top tab strip; Baserow, NocoDB, Grist, Notion, Coda, Smartsheet, Monday and ClickUp use a sidebar tree. Airtable users call tabs "pretty useless" with many tables and fall back on the dropdown ([Airtable community](https://community.airtable.com/base-design-9/better-way-to-manage-table-tabs-30804)); SeaTable's official advice is to shorten names to emojis ([SeaTable help](https://seatable.com/help/use-emojis-table-names-seatable/)). Airtable's hide feature removes a table from the bar and is explicitly "cosmetic, not access control", since data stays reachable through search, linked records and API ([Airtable support](https://support.airtable.com/articles/6134745429-creating-and-managing-tables-in-airtable)). Users reported the hidden-tables tab with a count and a crossed-out-eye unhide control, and complained that unhide was undiscoverable ([Airtable community](https://community.airtable.com/other-questions-13/hiding-tables-solved-14027)). Hide was requested for about seven years, and users conflated it with permissions, so KDOps's copy must not imply security. A community-reported Ctrl/Cmd+J jump-to-table shortcut and a popup that opened empty are user reports and not official documentation ([Airtable community](https://community.airtable.com/base-design-9/how-can-i-see-all-tables-in-a-base-29595)).

Persistence varies: Notion hiding is per user ([Notion help](https://www.notion.com/help/customize-your-sidebar)), Coda hiding is doc-wide and Doc Makers only ([Coda help](https://help.coda.io/en/articles/3544017)), NocoDB bookmarks are private ([NocoDB bookmarks](https://nocodb.com/docs/product/bases/bookmarks)), and Airtable's scope is unconfirmed. NocoDB's bookmark flyout is the best documented list popover: search filters by title across folders, Esc returns to the full list, drag shows a drop line, and deleting a folder moves items to Ungrouped. Baserow offers a 5-second undo toast on table delete ([Baserow docs](https://baserow.io/user-docs/customize-a-table)). No source documents match highlighting, active-table markers, or per-table row counts in a switcher, and no source documents arrow-key behaviour in any table switcher, so those are KDOps design decisions and not copies. Drag reorder has no documented keyboard alternative anywhere, which is an accessibility gap KDOps can close cheaply with move up and move down actions.

## Accessibility and performance: a W3C-derived spec with named unknowns

The verified accessibility base is the W3C APG. An editable combobox keeps DOM focus on the input (`role="combobox"`) while `aria-activedescendant` points at the highlighted option in a `listbox`; Down moves into the list, Escape closes, Enter accepts, and Alt+Down opens without moving focus ([APG Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)). Multi-select listboxes use `aria-multiselectable="true"` with either `aria-selected` or `aria-checked`, never both; Space toggles, Shift+Arrow extends and Ctrl+A selects all ([APG Listbox](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/)). With `aria-activedescendant` the author must scroll the active item into view and keep pointer hover and keyboard state in sync ([APG Keyboard Interface](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/)). In a grid, Enter or F2 hands keys to the widget and Escape returns navigation ([APG Grid](https://www.w3.org/WAI/ARIA/apg/patterns/grid/)). AG Grid and Handsontable both implement this by treating portaled popup editors as inside the cell and by stopping grid key handling while the editor is open ([AG Grid](https://www.ag-grid.com/react-data-grid/component-cell-editor/), [Handsontable](https://handsontable.com/docs/javascript-data-grid/cell-editor/)). Radix Popover supplies `Popover.Anchor`, `onCloseAutoFocus` and `onInteractOutside` hooks needed for this ([Radix Popover](https://www.radix-ui.com/primitives/docs/components/popover)). SeaTable users reported a link modal that stayed open after selection with focus not returned ([SeaTable forum](https://forum.seatable.com/t/bug-calendar-view-6-0-linked-records-modal-stays-open-after-selecting-record-focus-not-returned/7229)), the failure to test for. Live-region result counts, chip remove-button behaviour in screen readers, and per-screen-reader `aria-activedescendant` quirks have no retrieved authoritative source; they must be tested with NVDA and VoiceOver before being claimed as accessible.

For performance, TanStack Virtual provides `estimateSize`, `measureElement`, a stable `getItemKey`, a default overscan of 1 (raise it to avoid blank rows) and `scrollToIndex` for keyboard-driven active options ([TanStack Virtual](https://tanstack.com/virtual/latest/docs/api/virtualizer)). PostgREST documents `ilike` with `*`, `in.(...)` with quoting for commas, `or=(...)` for multi-column search, and `limit`/`offset` or `Range` pagination; `Prefer: count=exact` slows with table size ([PostgREST filters](https://docs.postgrest.org/en/stable/references/api/tables_views.html), [PostgREST pagination](https://docs.postgrest.org/en/stable/references/api/pagination_count.html)). Not verified, and to be confirmed before relying on them: supabase-js `abortSignal` for cancelling stale searches, keyset pagination via composed `or`/`and`/`gt`, a 150-250 ms debounce range, trigram GIN indexing for fast `ilike '%x%'`, URL-length limits for batched `in.()` queries, and canvas `measureText` for chip fitting. These are standard techniques from general knowledge and not from fetched sources.

## Prioritised build list for KDOps Database

Effort is S (about a day or less), M (several days), L (a week or more). "Client-only" means React changes with no migration. Items marked UNVERIFIED rest on general knowledge and need a spike or screen-reader test.

| # | Item | Spec | Effort | Risk | Client-only or DB change |
|---|------|------|--------|------|--------------------------|
| 1 | Grid-yield and focus return for all pickers | While a picker is open, the grid key handler returns early for every key; picker is portaled and counted as inside the cell; Escape and commit return focus to the originating cell (`onCloseAutoFocus`). Test that clicks inside the portal do not reach grid handlers (React portal bubbling, UNVERIFIED). | S | Low | Client-only |
| 2 | Combobox/listbox ARIA and keyboard | Search input `role="combobox"` with `aria-controls`, `aria-expanded`, `aria-activedescendant`, `aria-autocomplete="list"`; list `role="listbox"`, `aria-multiselectable` for multi-link; options use `aria-checked` plus a visible tick. Up/Down, Home/End, Enter toggles and keeps open on multi-link, Escape clears the query then closes, Tab commits and closes. Scroll active option into view and sync hover with active state. | M | Medium (screen-reader quirks unverified) | Client-only |
| 3 | Picker stays open on multi-link, create row always visible | Never close after each pick on multi-link; show "Create 'query'" as the last row whenever no exact match and also when the query is empty (avoid Airtable's hidden-until-typing complaint). | S | Low | Client-only |
| 4 | Search beyond the display field, with stale-result protection | Server search across display field plus a configurable few text fields via `or=(...ilike.*x*)`, escaping `%`, `_`, `*`, `,`, `(`, `)` and double-quoting. Debounce about 200 ms, ignore responses whose query key is stale, cancel via abort signal only after confirming supabase-js support. | M | Medium (escaping bugs; NocoDB's regression shows the failure) | Client-only; add a trigram index only if timing proves slow (then DB change) |
| 5 | Virtualised, paged picker list | TanStack Virtual with 50-row pages fetched as the last items near view; overscan raised above 1; `scrollToIndex` for keyboard; total count shown ("showing 50 of 1,240"). Offset paging is acceptable for small targets; keyset only after verification. | M | Medium | Client-only (count uses planned or estimated count to avoid `exact` cost) |
| 6 | Full names and extra context in picker rows | Do not truncate hard; wrap two lines or show title tooltip; optional secondary text from a second field. | S | Low | Client-only; per-link "secondary field" setting would need a field-config column (small DB change) if made configurable |
| 7 | Chip cell: count-aware overflow | Keep the existing "+N"; make "+N" open the full list in a bounded scrollable popover; expose total count in tooltip; plain-text value for screen readers in the closed cell; remove buttons only in edit mode with `aria-label="Remove {name}"` and focus moved to next chip or the cell. | S | Low | Client-only |
| 8 | Optimistic link and unlink with rollback | Update cache first, write junction row, restore snapshot on error with a visible message, dedupe realtime echoes of own writes, write only on actual change (CLAUDE.md rule). | M | Medium (realtime echo and loops) | Client-only |
| 9 | Select editor: type-to-filter, create row, gated creation | Autofocused search; trailing "+ Create 'xyz'" when no case-insensitive exact match; per-field switch "Allow new options from cells" defaulting to off for non-admins; Enter selects highlighted; Backspace on empty input removes last chip. | M | Low to medium | Switch needs a field-settings flag (small DB or JSON-config change if config is already JSON; confirm schema) |
| 10 | Palette with fill and text colours, auto-rotation | 12 to 16 hues, separate fill and text colour, contrast checked in both themes; new options take the next unused hue by index. | S | Low | Client-only |
| 11 | Select paste and import rules | Split on comma, semicolon or newline; match case-insensitively to existing options; unmatched tokens are left blank by default with a summary toast offering "create these N options"; never merge tokens into one option. | M | Medium (data-loss perception) | Client-only |
| 12 | Options settings editor | Rows with drag handle, colour, name, delete; Enter adds; multi-line paste splits into options; one-shot "Sort A-Z" (not a locked mode); rename propagates by id. | M | Low | Client-only if cells store option ids; if cells store option text, rename needs a data migration (verify first) |
| 13 | Option usage count and safe delete | Show "used by N rows" in settings and confirm before delete (cells go empty); offer merge-into-another-option. | M | Medium | Needs a query; a count RPC or view is a DB change, a client-side count is not safe on large tables |
| 14 | Select and multi-select filters | Single: is, is not, is any of, is none of, empty, not empty. Multi: has any of, has all of, is exactly, has none of, empty, not empty; "none of" includes empty rows, and the UI says so. | M | Medium (interacts with the null-aware filter fix in cf8361a1) | Client-only if filters run in client; DB change if filters compile to SQL |
| 15 | Table switcher keyboard and search | Search input as combobox with the same ARIA spec; Up/Down/Enter/Esc; match highlighting; active-table marker; virtualise the list for large bases; global jump shortcut (Ctrl/Cmd+J is community-reported at Airtable only, so choose one that does not clash with the browser). | S to M | Low | Client-only |
| 16 | "N hidden" chip and discoverable unhide | Visible count chip opening the same popover scoped to hidden tables with a labelled "Show" action; copy states hide is cosmetic and not access control. | S | Low | Client-only |
| 17 | Per-base order, hidden and per-user favourites/recents | Order and hidden shared per base; optional per-user hidden override; favourites and recents per user; Move up/Move down buttons as keyboard alternative to drag; write only on real change. | M | Medium (profile-table realtime loop risk noted in CLAUDE.md) | Needs DB change if order or hidden are not already stored per base; per-user items need a user-scoped table or profile column |
| 18 | Strict link-target limits (view or filter) enforced in data layer | Picker filter by view or condition, plus server-side validation so paste and API cannot bypass it. | L | High (RLS or trigger logic) | DB change (constraint, trigger or RPC) |
| 19 | Non-AI "Suggestions" ranking review | Define and document how suggestions rank (recent, same-parent, text match); no competitor reference exists except AI-based Airtable. | S | Low | Client-only |

Order of work: items 1 to 3 and 7 first, because they fix correctness and discoverability with no schema risk; then 4, 5, 8 for scale; then the select group (9 to 12, 14); then the switcher group (15 to 17); defer 13 and 18 until a database change is justified.

## Conclusion

The research reframes the task from "add features" to "fix the contract". Competitors disagree on almost nothing visible (chips, search, create row, hide, count), yet their documented failures are all contract failures: closing after each pick, hidden create, truncation, silent paste merging, and filters that do not bind. KDOps can lead by getting the unglamorous parts right: grid-yield and focus return, a W3C-compliant combobox, search that spans fields, and paste that never merges options. None of this is documented as shipped by any competitor, which makes it an opportunity and also a warning: the keyboard spec here is derived from the W3C and from AG Grid and Handsontable, and it is untested against real screen readers.

Three open questions decide the DB-change items. First, whether select cells store option ids or option text, which determines whether rename and merge are cheap. Second, whether table order and hidden state already live per base. Third, whether filters compile to SQL or run in the client. Answer those from the repo before sizing items 12 to 14 and 17. Also run a short spike to confirm supabase-js abort support, keyset paging and the trigram-index need, because the notes could not verify any of them.
