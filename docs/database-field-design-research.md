# Polished grids share one outline, short text, tokens

The best spreadsheet-databases feel uncluttered because they obey four rules, and KDOps can adopt all four without a redesign. First, a cell owns exactly one outline and the editor inside it is borderless, so no nested box appears. Second, the cell shows the shortest useful text and moves detail (seconds, time zone, full link lists) into a tooltip, the editor or an expanded state. Third, every display decision comes from per-field configuration through one formatter and one palette of tokens, never from ad-hoc strings or hex values. Fourth, interactive affordances (the `+`, the remove `x`, clickable chips) appear only when the cell is active, so single-click selection is never hijacked. The strongest evidence is open-source code (Baserow, NocoDB, Teable, Grist) and component-library defaults (react-day-picker, shadcn/ui, Radix); **Airtable, Notion, Attio, Coda, Linear and Google Sheets publish almost no pixel specs**, so every pixel number below is either read from open-source code (labelled as sourced) or a recommendation (labelled as such). The final sections give a prioritised spec and list what could not be verified.

## One outline per cell: the edit model that prevents the nested box

Every product that documents it uses two states: a selected cell driven by arrows, and an edit state entered with Enter or F2 and left with Esc (discard) or Enter/Tab (save). The W3C grid pattern says Enter or F2 moves focus into the cell's input, a second F2 returns to grid navigation, and Escape restores navigation and may undo the edit ([WAI-ARIA APG grid](https://www.w3.org/WAI/ARIA/apg/patterns/grid/)). Baserow, NocoDB, Grist and Airtable all match this, and field type changes what Enter does: Baserow opens an upload dialog for files, a selection modal for links and toggles booleans ([Baserow shortcuts](https://baserow.io/user-docs/baserow-keyboard-shortcuts)); NocoDB opens a modal or picker for linked cells ([NocoDB shortcuts](https://nocodb.com/docs/product-docs/getting-started/keyboard-shortcuts)); Grist toggles checkboxes on Enter and saves-and-moves on Tab ([Grist shortcuts](https://support.getgrist.com/keyboard-shortcuts/)). Airtable also supports Ctrl/Cmd+; to set a date field to now, Space to expand the record and Shift+Space to expand the cell ([Airtable shortcuts](https://support.airtable.com/docs/airtable-keyboard-shortcuts)). Grist adds Ctrl+D fill down and Ctrl+Shift+; for date-time ([Grist shortcuts](https://support.getgrist.com/keyboard-shortcuts/)).

The doubled box and glow ring in the KDOps screenshots has a mechanical cause that no product documents but MDN explains: browsers always show a focus indicator on a text input, so a native input mounted inside an already-outlined cell receives a second ring from any global `:focus-visible` style ([MDN :focus-visible](https://developer.mozilla.org/en-US/docs/Web/CSS/:focus-visible)). The fix is to put the single ring on the cell (selected and editing share the same colour and thickness, only fill or shadow changes) and reset inner controls inside the grid only. Do not remove focus styles globally, because WCAG requires a visible indicator with at least 3:1 contrast ([MDN :focus-visible](https://developer.mozilla.org/en-US/docs/Web/CSS/:focus-visible)). NocoDB's currency cell shows the same field with the full raw amount on click-in rather than swapping to a different-looking control ([NocoDB currency](https://nocodb.com/docs/product-docs/fields/field-types/numerical/currency)), which is the "same cell, different text" model to copy.

Accessibility follows the same structure. The APG roles are `grid` > `row` > `gridcell`/`columnheader`, with `aria-readonly` on non-editable cells, `aria-selected` on selection, and `aria-rowcount`/`aria-colcount` plus per-cell indexes whenever rows or columns are virtualised or hidden. The grid is one tab stop using roving tabindex ([APG grid](https://www.w3.org/WAI/ARIA/apg/patterns/grid/), [APG data grids example](https://www.w3.org/WAI/ARIA/apg/patterns/grid/examples/data-grids/)). AG Grid warns that screen readers assume all elements are in the DOM, which conflicts with virtualisation, and that some readers do not announce state changes on the focused cell ([AG Grid accessibility](https://www.ag-grid.com/javascript-data-grid/accessibility/)), so a real screen-reader test is required. The same page says colour must never be the only carrier of meaning, which matters for negative numbers and select pills. Animations should run only under `prefers-reduced-motion: no-preference` ([web.dev](https://web.dev/articles/prefers-reduced-motion)).

## Dates: short cell text, typed input first, a calendar with one accent

Products converge on a per-field display preset (Airtable: Local, Friendly, US, European, ISO), an "include time" toggle, a 12h/24h choice, and a time-zone label that is opt-in ([Airtable date field](https://support.airtable.com/v1/docs/date-and-time-field)). Baserow stores UTC and has a separate "Show timezone" option ([Baserow timezones](https://baserow.io/user-docs/working-with-timezones)); Attio keeps timezone-less Date and instant Timestamp as separate attribute types ([Attio date](https://docs.attio.com/rest-api/attribute-types/attribute-types-date), [Attio timestamp](https://docs.attio.com/rest-api/attribute-types/attribute-types-timestamp)); Grist separates Date from DateTime and sets a display timezone ([Grist column types](https://support.getgrist.com/col-types/)). The KDOps cell text `02 Mar 2026, 12:45:00 am (GMT+1)` therefore contradicts the market pattern on two counts: seconds and zone are shown by default. Recommended cell text is `02 Mar 2026` or `02 Mar 2026, 12:45 am`, with seconds and zone only in the tooltip and editor, plus an opt-in "Show time zone" field setting. NocoDB also offers weekday-prefixed formats that are display-only ([NocoDB Date](https://nocodb.com/docs/product-docs/fields/field-types/date-time-based/date)). No product documents how a too-narrow date column degrades, so the ladder in the spec (full, compact, numeric, ellipsis) is a recommendation.

Typing is the primary entry path. Airtable parses typed dates by the field's format and also accepts unpadded and month-name input, assuming the current year when omitted ([Airtable date field](https://support.airtable.com/v1/docs/date-and-time-field)); NocoDB accepts unpadded `5/5/2026` ([NocoDB Date](https://nocodb.com/docs/product-docs/fields/field-types/date-time-based/date)); Grist's editor wraps a datepicker with a "today" button and turns calendar arrow-navigation on only once the calendar has focus, so typing wins ([Grist DateEditor.ts](https://github.com/gristlabs/grist-core/blob/main/app/client/widgets/DateEditor.ts)). Grist stores unparseable text as-is, which is risky for a date column; the recommendation is to reject and keep the editor open. Natural-language phrases ("tomorrow") are documented only for Notion page mentions, not date cells ([Notion shortcuts](https://www.notion.com/help/keyboard-shortcuts)).

For the calendar itself, no product publishes pixel sizes, so the numbers come from component libraries. react-day-picker defaults to a 44px day cell, a 42px button and a 0.3s animation ([react-day-picker styling](https://daypicker.dev/v9/docs/styling)); the shadcn calendar uses a 32px cell (`--spacing(8)`), `bg-primary` for selected, `bg-accent` for today, and a 3px `ring-ring/50` focus ring on the focused day ([shadcn calendar.tsx](https://raw.githubusercontent.com/shadcn-ui/ui/main/apps/v4/registry/new-york-v4/ui/calendar.tsx)). The reported KDOps defects (teal selected square with a gold ring, one gold weekday letter) fit this source: if the theme's `--ring` is gold and `--primary` teal, a focused selected day shows two hues, and react-day-picker exposes only a single `--rdp-weekday-opacity`, so a lone coloured weekday must be custom CSS (inference). The keyboard map is standardised: arrows move by day/week, PageUp/PageDown by month, Shift+PageUp/PageDown by year, Home/End to week edges ([react-day-picker accessibility](https://daypicker.dev/guides/accessibility), [APG date picker dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/examples/datepicker-dialog/)). Notion's picker contains Remind, End date, Include time, Date format and timezone, and Clear ([Notion properties](https://www.notion.com/help/database-properties)); its End-date toggle is the model for ranges. The time row ("Time 3 : 14 AM PM") should become one typed `h:mm` input plus an AM/PM segmented control, because Airtable and Baserow both treat time as typed text parsed by field format ([Baserow date fields](https://baserow.io/user-docs/date-and-time-fields)).

## Linked records: one clipped row, labels resolved, details on activation

No grid shows hundreds of chips. Baserow's inactive link cell is a single non-wrapping flex row with `overflow:hidden`, 4px gap, 22px-high chips with 13px text, 5px side padding and a neutral-100 fill, and chips that do not fit are simply clipped. When the cell is active it grows, wraps, caps at `max-height:300px` with internal scroll, tints chips blue, and reveals a remove `x` per chip and a 22px `+` chip ([Baserow many_to_many.scss](https://raw.githubusercontent.com/bram2w/baserow/develop/web-frontend/modules/core/assets/scss/components/views/grid/many_to_many.scss)). Teable's React chip is 24px tall, 13px text, 6px radius, 8px padding, with a `title` tooltip and an unlink `x` that keeps its width at opacity 0 so nothing reflows ([Teable CellLink.tsx](https://raw.githubusercontent.com/teableio/teable/HEAD/packages/sdk/src/components/cell-value/cell-link/CellLink.tsx), [LinkTag.tsx](https://raw.githubusercontent.com/teableio/teable/HEAD/packages/sdk/src/components/editor/link/LinkTag.tsx)). NocoDB draws 24px chips (brand-50 fill, brand-500 text, 13px weight 500), stops at the row limit and draws an ellipsis glyph, and only opens a chip when the cell is already active ([NocoDB ManyToMany.ts](https://raw.githubusercontent.com/nocodb/nocodb/HEAD/packages/nc-gui/components/smartsheet/grid/canvas/cells/LTAR/ManyToMany.ts), [ItemChip.vue](https://raw.githubusercontent.com/nocodb/nocodb/HEAD/packages/nc-gui/components/virtual-cell/components/ItemChip.vue)). The existing KDOps "+162" badge is therefore a sensible addition (none of the three read renderers draws a +N, so it is a design choice, not a convention); the real defects are five-character chips and raw ids, since every product above lets a name take the cell width up to an ellipsis.

The performance pattern is equally consistent. Baserow's row payload carries `{id, value}` pairs with the linked row's primary text already resolved, caps the grid load at 20 per cell (`LINKED_ITEMS_DEFAULT_LOAD_COUNT = 20`), shows a loading chip when a cell hits the cap, and fetches the full row only when the cell is activated ([Baserow constants.js](https://raw.githubusercontent.com/baserow/baserow/HEAD/web-frontend/modules/database/constants.js), [FunctionalGridViewFieldLinkRow.vue](https://raw.githubusercontent.com/baserow/baserow/HEAD/web-frontend/modules/database/components/view/grid/fields/FunctionalGridViewFieldLinkRow.vue)). Notion truncates relation values at 25 references per page response ([Notion API](https://developers.notion.com/reference/property-value-object)). Pickers never load a whole table: Baserow pages 10 rows with a 400ms-debounced search ([Baserow docs](https://baserow.io/user-docs/link-to-table-field), [SelectRowContent.vue](https://raw.githubusercontent.com/baserow/baserow/HEAD/web-frontend/modules/database/components/row/SelectRowContent.vue)), while Teable fetches only the visible range, offers an "All / Selected" toggle, and caps a bulk selection at 1,000 ([Teable EditorMain.tsx](https://raw.githubusercontent.com/teableio/teable/HEAD/packages/sdk/src/components/editor/link/EditorMain.tsx), [LinkList.tsx](https://raw.githubusercontent.com/teableio/teable/HEAD/packages/sdk/src/components/editor/link/LinkList.tsx)). Airtable allows up to 100,000 links per cell on its largest plan ([Airtable linking](https://support.airtable.com/docs/linking-records-in-airtable)). The never-show-an-id rule is also sourced: Airtable shows "Unnamed record" ([community thread](https://community.airtable.com/base-design-9/linked-record-showing-unnamed-record-29671)), Baserow shows muted grey "unnamed row N" ([GridViewFieldLinkRow.vue](https://raw.githubusercontent.com/baserow/baserow/HEAD/web-frontend/modules/database/components/view/grid/fields/GridViewFieldLinkRow.vue)), and Teable shows a muted "record deleted" label ([LinkCard.tsx](https://raw.githubusercontent.com/teableio/teable/HEAD/packages/sdk/src/components/editor/link/LinkCard.tsx)). Note Teable's `title = 'Unnamed record'` default only fires for `undefined`, so an empty string still renders blank; test for both. Where 20 to 190 links per row is normal, a rollup (Notion offers count, sum, average, earliest, latest and more) is the right summary ([Notion rollups](https://www.notion.com/help/relations-and-rollups)).

## Numbers, currency, duration and select pills: one formatter, one palette

All products store the raw number and treat format as display config. Airtable allows 0-8 decimals for Number, 0-7 for Currency, and stores percent as a fraction (12.3% as 0.123) ([Airtable field model](https://airtable.com/developers/web/api/field-model)); Baserow supports 0-10 decimals, prefix/suffix text and "allow negatives" that clamps typed negatives to 0 ([Baserow number](https://baserow.io/user-docs/number-field)); Attio allows one currency per attribute, up to four stored decimals, and maps display to `Intl.NumberFormat`'s `currencyDisplay` ([Attio currency](https://docs.attio.com/docs/attribute-types/attribute-types-currency)); Notion's format enum includes `nigerian_naira` ([Notion property object](https://developers.notion.com/reference/property-object)). NocoDB documents abbreviation precisely: 1234567.89 shows as `$1,234,567.89`, or `$1.23M` in Auto; abbreviation is display-only, clicking in shows the full amount, copying copies the full amount, and pasting `1.2M` stores 1200000 while typing a suffix is rejected ([NocoDB currency](https://nocodb.com/docs/product-docs/fields/field-types/numerical/currency)). Everything needed is native: `Intl.NumberFormat` supports `currencyDisplay` (`symbol`, `narrowSymbol`, `code`), `currencySign: "accounting"` for parenthesised negatives, `notation: "compact"` and `signDisplay` ([MDN Intl.NumberFormat](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/NumberFormat/NumberFormat)), and `font-variant-numeric: tabular-nums` aligns digits ([MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/font-variant-numeric)). The three KDOps symptoms (`₦8,500,000.00`, `NGN204,876,107.00`, `603,123.664`) are what you get when `currencyDisplay` and precision are chosen at call sites; one `formatMoney` used by cell, footer, rollup and formula fixes all three. Airtable's duration field stores seconds, offers `h:mm` through `h:mm:ss.sss`, and handles larger units with a plain number ([Airtable duration](https://support.airtable.com/docs/duration-field-type)); its typed-input rules are only community-reported.

Select pills are where "polished, never cluttered" is most visible. Notion's ten option colours (default, gray, brown, orange, yellow, green, blue, purple, pink, red) assign randomly at creation, names are unique ignoring case and cannot contain commas ([Notion property object](https://developers.notion.com/reference/property-object), [Notion properties](https://www.notion.com/help/database-properties)); Airtable offers ten hues in four tones (Light2, Light1, Bright, Dark1) and allows 10,000 options and 1,000 selected per cell ([Airtable field model](https://airtable.com/developers/web/api/field-model), [Airtable multiple select](https://support.airtable.com/docs/multiple-select-field)); Baserow offers 15 colours and a pinned "Create new option" when typed text matches nothing ([Baserow single select](https://baserow.io/user-docs/single-select-field)); Grist lets you add a typed value as a choice and enter it in one step, and Backspace/Delete removes selected values ([Grist column types](https://support.getgrist.com/col-types/)). Atlassian's lozenge guidance caps width at 200px, notes truncated lozenge text cannot be reached by keyboard focus, prescribes sentence case, and warns against colour as the only signal ([Atlassian lozenge](https://atlassian.design/components/lozenge/usage)).

For the palette, use Radix's 12-step semantics: step 3 is a component background, 6-7 are subtle borders, 11 and 12 are text ([Radix scale](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale)). The researcher computed contrast from Radix's hex values (not a published figure): step-11 text on step-3 fills falls to 3.99-5.36:1 in light mode and fails 4.5:1 for 8 of 10 hues, whereas step-12 text gives 10.3-14.3:1 light and 11.4-13.7:1 dark. Pills should therefore use step 3 fill, step 7 border and step 12 text, with one rule for both themes. The token table is in the spec below (hex from [Radix light.ts](https://raw.githubusercontent.com/radix-ui/colors/main/src/light.ts) and [dark.ts](https://raw.githubusercontent.com/radix-ui/colors/main/src/dark.ts)).

## Attachments, rating, checkbox, progress and button: small, centred, quiet until active

Open-source grids give the only hard numbers. Attachments are rounded thumbnails that scale with row height: Baserow 22px (26px at large) with a 1px neutral-400 border, a 22px file-icon box for non-images, 2-5px gaps and a 22px `+` tile that appears only when the cell is active ([Baserow file.scss](https://github.com/baserow/baserow/blob/develop/web-frontend/modules/core/assets/scss/components/views/grid/file.scss)); NocoDB uses 24, 32 and 64px tiles by row height with an 8px gap, 4px radius, a 1px gray-300 border, a red icon tile for failed loads and a file-type icon fallback ([NocoDB Attachment.ts](https://github.com/nocodb/nocodb/blob/develop/packages/nc-gui/components/smartsheet/grid/canvas/cells/Attachment.ts)); Teable subtracts 3px padding top and bottom from the row height and draws a 20px `+` only when editable and active ([Teable imageCellRenderer.ts](https://github.com/teableio/teable/blob/develop/packages/sdk/src/components/grid/renderers/cell-renderer/imageCellRenderer.ts)). All three clip rather than draw +N. Airtable previews images and common documents on click and documents a 5 GB per-attachment limit, with actionable error strings ([Airtable attachment field](https://support.airtable.com/docs/attachment-field)).

Rating icons are 16-22px with 2-3px gaps: Baserow 22px, default dark-orange, empty `neutral-200`, hover tint at 0.6 opacity, digits 0-9 set the value and clicking the current value clears it ([Baserow rating.scss](https://github.com/baserow/baserow/blob/develop/web-frontend/modules/core/assets/scss/components/rating.scss), [GridViewFieldRating.vue](https://github.com/baserow/baserow/blob/develop/web-frontend/modules/database/components/view/grid/fields/GridViewFieldRating.vue)); NocoDB defaults to `#fcb401` with 1.5px gaps ([NocoDB Rating/Editor.vue](https://github.com/nocodb/nocodb/blob/develop/packages/nc-gui/components/cell/Rating/Editor.vue)); Teable uses 16px icons, 3px gap, `yellow-400` and a 30%-alpha hover preview ([Teable ratingCellRenderer.ts](https://github.com/teableio/teable/blob/develop/packages/sdk/src/components/grid/renderers/cell-renderer/ratingCellRenderer.ts)). Checkboxes are 14-20px and centred: NocoDB draws unchecked at 30% alpha (70% on hover), toggles on click only if the cell is already active, and swaps icons over 100ms ([NocoDB Checkbox/Editor.vue](https://github.com/nocodb/nocodb/blob/develop/packages/nc-gui/components/cell/Checkbox/Editor.vue)); Baserow draws a 20px box whose border shows only when active ([Baserow boolean.scss](https://github.com/baserow/baserow/blob/develop/web-frontend/modules/core/assets/scss/components/views/grid/boolean.scss)). NocoDB's percent cell offers a bar (min 4px, fully rounded) or an 18px circle with 2px stroke, clamped 0-100 ([NocoDB ProgressBar.vue](https://github.com/nocodb/nocodb/blob/develop/packages/nc-gui/components/cell/Percent/ProgressBar.vue)). Buttons are 24px-high, 4px-radius, 12px-label pills, min 60px and max 126px wide, with 0.8 opacity and ignored clicks while loading ([Teable buttonCellRenderer.ts](https://github.com/teableio/teable/blob/develop/packages/sdk/src/components/grid/renderers/cell-renderer/buttonCellRenderer.ts)). Collaborator chips are 24px high with a 20px avatar, 12px name and an `x` only when active ([Teable userCellRenderer.ts](https://github.com/teableio/teable/blob/develop/packages/sdk/src/components/grid/renderers/cell-renderer/userCellRenderer.ts)). Computed cells reuse the result type's renderer in read-only mode (Baserow) and show an explicit orange `ERR!` token on failure (NocoDB) ([Baserow GridViewFieldFormula.vue](https://github.com/baserow/baserow/blob/develop/web-frontend/modules/database/components/view/grid/fields/GridViewFieldFormula.vue), [NocoDB Formula.ts](https://github.com/nocodb/nocodb/blob/develop/packages/nc-gui/components/smartsheet/grid/canvas/cells/Formula.ts)). Row heights are 33/55/99px in Baserow, 32/60/90/120 in NocoDB and 32/56/84/108 in Teable ([Baserow variables.scss](https://github.com/baserow/baserow/blob/develop/web-frontend/modules/core/assets/scss/variables.scss), [NocoDB cell.ts](https://github.com/nocodb/nocodb/blob/develop/packages/nc-gui/utils/cell.ts), [Teable const.ts](https://github.com/teableio/teable/blob/develop/apps/nextjs-app/src/features/app/blocks/view/grid/const.ts)).

## Implementation spec for KDOps Database, prioritised

Every row below is a **recommendation** unless a source is named in brackets. Where a number is sourced it is the open-source value I am anchoring to; where it is not, it is my synthesis. Tokens go on `:root` with a dark override and are mapped into Tailwind theme colours; no hex in components.

**Priority 0: remove the visible defects (do first)**

| Item | Spec |
|---|---|
| Single outline | Ring on the cell wrapper only: `box-shadow: inset 0 0 0 2px var(--grid-active-ring)` (inset does not shift layout). Selected and editing use identical ring; editing adds `background: var(--grid-cell-editing-bg)` and optional soft shadow. Inner editors: `.db-cell-editor :where(input,textarea,select){outline:none;box-shadow:none;border:0;background:transparent;border-radius:0}`. Ring contrast at least 3:1 (WCAG 1.4.11). |
| No-shift rule | Renderer and editor share one class for padding, font, line-height, text-align, `font-variant-numeric`. Editor `w-full h-full box-border`. |
| Money/number formatter | One `formatMoney(value,{code,display,decimals,sign})`. Default NGN: `Intl.NumberFormat('en-NG',{style:'currency',currency:'NGN',currencyDisplay:'narrowSymbol'})`, 2 decimals (verify the exact `en-NG` output in the runtime). Right-aligned, `tabular-nums`. Used by cell, footer, rollup, formula. Negatives: minus or parentheses, red only as an addition. |
| Date cell text | `02 Mar 2026` / `02 Mar 2026, 12:45 am`; `nowrap`, `truncate`, tooltip with seconds and `GMT+1`. Zone label is a field option, off by default. Narrow ladder: full, `12:45a`, `02/03/26 12:45`, ellipsis. Minimum comfortable width about 150-160px at 13px (estimate, not measured). |
| Link chips | Chip text `label?.trim() \|\| "Unnamed record"` (muted); deleted target = muted "Deleted record"; never render an id or a string matching `rec...`/uuid; skeleton chip while loading. Chip may use the full cell width (`max-w-full truncate`), not a 5-character stub. Keep the `+N` badge, add title tooltip listing the rest. |
| Date picker colours | One accent: selected `bg-primary`, focus-visible ring `ring-2 ring-primary ring-offset-2` (same hue), today = bold or 1px inset ring (no fill), uniform muted weekday header with no per-day highlight, outside days 35-50% opacity. |

## What could not be verified

No pixel specs (chip height, padding, radius, popover width, colours, motion) were found for Airtable, Notion, Attio, Coda, Linear or Google Sheets, and none of the ten products documents how a date cell degrades when narrow, what its multi-select overflow looks like, or its popover open/close timings. Airtable's outline implementation, fill-handle size, thousands-separator styles, abbreviation units, typed-currency editing behaviour, lightbox chrome and "+N" overflow are undocumented in what was fetched. Teable keyboard and edit-state docs were not found; Teable's date-format options came from a Chinese-language page and its decimal range from a GitHub mirror. Coda date details came from a search summary of a page that returned 403. Linear's due-date shortcut conflicts between sources (Cmd+D in the changelog, Shift+D in a docs summary). Notion's date display formats and natural-language entry in date cells could not be confirmed. Attio's cell behaviour for many-record references is undocumented in the pages found. Baserow's backend cap of 20 linked items was inferred from frontend constants, not the serializer. The react-day-picker focus class names and whether v9 renders `role="grid"` must be checked against the installed version. Contrast ratios for the palette were computed by the researcher, border contrast (WCAG 1.4.11) was not computed, and the `en-NG` currency string was not run. Tri-state checkbox, drag-fill bulk toggle, copy behaviour of computed cells, rich-text toolbar contents and screen-reader announcement wording for edit mode have no source. Status-type fields (To do/Doing/Done groups) in Notion, Attio and Coda were not researched. The 200-row render cap, the 100-option warning, the narrow-date ladder, the `+N` badges and all motion timings above are recommendations, not benchmarks.

## Conclusion

The most useful finding is negative: polish in these products is not a pixel secret but a discipline, and the open-source grids show it is cheap to copy. The same four moves recur across field types (one owner of the outline, reveal-on-active affordances, display-only formatting from config, and a bounded first render with details deferred), so KDOps can build a small set of shared primitives (cell shell, formatter, pill, chip, popover) and let each field type configure them instead of designing each cell separately.

The second implication is sequencing. Almost every visible KDOps defect (nested box, `NGN204,876,107.00`, `recNc` chips, a date overflowing, a two-hue calendar) maps to a missing shared rule rather than a missing feature, so the Priority 0 table should ship as one change set verified in the running app, followed by the keyboard and picker work. Because the market evidence is thinnest exactly where KDOps cares most (Airtable's own specs), plan one hands-on pass inspecting Airtable's live DOM and a screen-reader test before treating any recommended number as final.
