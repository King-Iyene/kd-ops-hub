# Rebuild KDOps formulas, links and settings

Build the formula editor on CodeMirror 6, lazy-loaded, with `{Field}` references drawn as pills over unchanged formula text, so the existing parser keeps working and copy, paste and undo stay plain text. The researcher measured CodeMirror at about 66.5 KB gzipped for the core and 116.5 KB with autocomplete, lint, language and commands, against 724 KB to 1.22 MB for Monaco (measured locally with esbuild, not independently confirmed) ([npm: @codemirror/view](https://www.npmjs.com/package/@codemirror/view), [npm: monaco-editor](https://www.npmjs.com/package/monaco-editor)). For linked records, the fix for clipped chips is to let a chip use the cell width up to an ellipsis, reserve room for a measured "+N" badge, and put the full list in a tooltip and a searchable picker. Rollup setup should be one dialog with three selects in a fixed order (link field, target field, function), a type-aware function menu with plain descriptions, a result-format row and a sample-row preview; no researched product ships that preview. The settings panel should regroup existing controls into Format, Rules, Default and Advanced, with a preview strip rendered by the real formatter. Most of this is client-side; server or database work is needed only for atomic rename rewrites, rollups that sort, filter or group, one-to-one enforcement, and shared diagram layouts. Cell and chip specs from `docs/database-field-design-research.md` carry over; the baseline is the audit in `docs/database-field-parity.md` (about 73 formula functions with preview and autocomplete, per-cell rollup fetches, formulas that reference fields by name).

## CodeMirror 6 with pills over unchanged text fits the formula editor

**How the leaders handle it.** Two families exist. Airtable, Teable, NocoDB and Grist keep the reference as coloured text; Notion and Coda render tokens. Airtable colours functions green, fields purple, numbers orange-brown and strings teal, and rewrites formulas when a field is renamed ([Airtable formula overview](https://support.airtable.com/docs/formula-field-overview), [formula writing tips](https://support.airtable.com/docs/formula-writing-tips-for-beginners)). Notion shows `prop("X")` as a token named `X` and pastes the full text on copy; that claim comes from third-party guides, not Notion's own help ([Thomas Frank](https://thomasjfrank.com/formulas/the-formula-editor/)). Coda's pills draw complaints: no raw-text escape, and Backspace beside a pill can break it permanently ([Superhuman Connect thread](https://connect.superhuman.com/t/i-cant-edit-those-pills-in-my-formulas/41264)). No source gives hex values, pill sizes or fonts, so every number below is a recommendation unless a source is named.

**Why CodeMirror.** The formula is text that an existing TypeScript parser consumes, so a text-first editor fits better than the node-tree editors (Lexical, Slate, TipTap), which need serialising on every keystroke and hand-built highlighting, lint and completion. Baserow's TipTap input needed extra extensions (SmartDeletion, ArrowKeyNavigation, zero-width-space handling) to make the caret behave around inline atoms ([Baserow](https://gitlab.com/baserow/baserow/-/raw/develop/web-frontend/modules/core/components/formula/FormulaInputField.vue)). n8n runs CodeMirror 6 with unit-tested plugins ([n8n](https://raw.githubusercontent.com/n8n-io/n8n/master/packages/frontend/editor-ui/package.json)). NocoDB does pills over text on Monaco: braces stay in the model, hidden by decorations ([useFormulaChips.ts](https://raw.githubusercontent.com/nocodb/nocodb/develop/packages/nc-gui/components/smartsheet/column/formula/useFormulaChips.ts)). CodeMirror does this natively with `Decoration.replace` plus `EditorView.atomicRanges`, both fed from one StateField ([@codemirror/view d.ts](https://www.npmjs.com/package/@codemirror/view)). A textarea cannot make true pills; Monaco is excluded on size and because its README says mobile browsers are unsupported.

**Recommended design.** The dialog is a multi-line editor (13px monospace, 22px line height, minimum four lines, resizable) in Notion's layout: field and function list on the left, detail on the right, preview below ([Notion help](https://www.notion.com/help/formulas)). Autocomplete opens on `{` with field names and on the first typed letter with function names; Ctrl+Space opens it explicitly. Each row shows a type icon, with the signature as `detail` and the description as `info`. Up and Down move, Tab and Enter accept, Esc closes; Excel and Notion agree, and Airtable's Tab ambiguity (indent versus accept) is the cautionary case ([Microsoft](https://support.microsoft.com/en-us/excel/use-formula-autocomplete), [Airtable community thread](https://community.airtable.com/announcements-6/product-update-formula-editor-improvements-1604)). Choosing a field inserts `Name}`. Configure `closeBrackets` and `bracketMatching` for `()` only, because `{` is otherwise treated as an ordinary bracket pair.

Inside parentheses, a tooltip shows the signature with the active argument in bold, a one-line description, one example and a "Full reference" link, collapsible as in Excel for the web ([Excel blog](https://techcommunity.microsoft.com/blog/excelblog/formula-argument-assistance/3762262)). No official signature-help extension exists in the CodeMirror packages checked, so build it with `showTooltip` from a pure `activeArgument(text, pos)` function. A reference panel lists functions by category (text, number, date, logic, array) with search, as NocoDB does ([NocoDB formula docs](https://nocodb.com/docs/product-docs/fields/field-types/formula/formula)). One `FUNCTIONS` array (name, category, signature, description, example) feeds completion, hints, reference and tests.

Errors come from the existing parser: catch the throw, convert its position to a lint `Diagnostic`, delay 300ms, and call `forceLinting` on blur and save. Underline in red with a hover message. Use yellow only for non-blocking warnings; Coda's type warnings need type information the parser may lack ([Coda](https://connect.superhuman.com/t/launched-new-features-to-prevent-costly-formula-errors/24319)). Below the editor, a preview line shows the value formatted by the shared formatter with a type icon, or the first error with its message. Notion previews on a row and does not block saving on errors (third-party guide); recommended here: preview on a chosen sample row (default first) and block saving only on parse errors. Test multiline formulas early; Airtable's checker reportedly flags valid ones.

Pills are 20px high, 4px radius (match the app-wide select-pill radius), 6px horizontal padding, 12px/16px weight 500, with a 12px field-type icon; the widget is a plain inline `<span>`, never `contenteditable`, with `aria-label="field Amount"`. Theme through CSS variables in `EditorView.theme`, so dark mode flips variables with no editor reconfigure. Syntax-colour contrast was not computed; check 4.5:1.

**Pill behaviour and the Coda lesson.** Backspace or Delete removes a whole pill, a click beside a pill places the caret (return `false` from `ignoreEvent`), and a "Plain text" toggle drops the pill extension and shows raw `{Field}` text coloured purple. Because the document text never changes, copy gives plain formulas and undo treats pills and typing uniformly. The pill pattern is where CodeMirror's IME bug reports concentrate (Safari, Android, composition next to a widget). Ship it behind a flag, with mark-only colouring (n8n's approach) as the lower-risk fallback ([CM forum IME thread](https://discuss.codemirror.net/t/bug-ime-selection-is-not-updated-when-decoration-mark-contains-multiple-decoration-replace-decorations/9785)). Keep every `@codemirror/*` import in one dynamically imported module, use `resolve.dedupe` in Vite, and show the existing textarea as the Suspense fallback.

**Renames.** Airtable and Baserow rewrite formula text on rename, and Baserow marks formulas broken on delete and heals them if a field with the old name returns ([Baserow technical guide](https://baserow.io/docs/technical/formula-technical-guide)). No source confirms any competitor stores ids. Recommended now: a pure `renameFieldInFormula(text, old, new)` built on the tokenizer, not a regex, applied to every formula field, and to button templates, in the same rename action; a deleted field leaves a red pill that heals if a field of that name is recreated. Storing ids is better long term (the structure spec plans it) but needs a data migration. Two client writes can fail between them and leave broken formulas, so an atomic server function is the safe version.

## Link chips name the record, count the rest and open a picker

**The overflow evidence.** No product publishes chip pixel specs. Airtable gives no indication that more linked records exist in a clipped link cell, which is the owner's exact complaint; this comes from user reports in the Airtable community, not from Airtable ([community thread](https://community.airtable.com/legacy-product-ideas-75/link-to-another-record-fields-visual-indicator-that-there-are-more-linked-records-43190)). Baserow clips inactive chips on one row and, when the cell is active, wraps them to a 300px scroll with a remove `x` per chip and a trailing `+` ([many_to_many.scss](https://raw.githubusercontent.com/bram2w/baserow/develop/web-frontend/modules/core/assets/scss/components/views/grid/many_to_many.scss)). NocoDB's older Links type shows only "N Links" ([Links.ts](https://raw.githubusercontent.com/nocodb/nocodb/develop/packages/nc-gui/components/smartsheet/grid/canvas/cells/Links.ts)). None of the read renderers draws a "+N", so a visible count is a differentiator, not parity. The current KDOps renderer was not read; the complaint suggests a count that ignores what CSS clips (inference, to verify).

**Recommended chip.** Height 22px in the 32px row, 13px text, 6px radius (Teable) ([LinkTag.tsx](https://raw.githubusercontent.com/teableio/teable/HEAD/packages/sdk/src/components/editor/link/LinkTag.tsx)), 8px horizontal padding, 4px gap. Text is `label?.trim() || "Unnamed record"` in muted style, and a deleted target reads "Deleted record"; an id never renders. The chip takes `max-w-full` with an ellipsis, so "Project Alpha" shows whole when it fits. Overflow works as follows: measure each chip once, reserve the width of the "+N" badge (digits of N times the digit width plus padding), show the chips that fit, and set N to total minus shown. Always show at least one truncated chip plus the badge; if even that does not fit, show "3 links" (NocoDB's count mode, also an optional display style for 100+ links). The badge is a focusable button with a tooltip listing up to ten names then "and k more", and click opens the picker. At taller row heights (56, 84, 112px) chips wrap and the badge appears only when lines run out. The active cell wraps to a 300px scroll with a chip `x` (width reserved at opacity 0 so nothing shifts, per Teable) and a 22px `+`. Chip colour is a decision (below): the Radix blue tokens (#e6f4fe / #8ec8f6 / #113264 light, #0d2847 / #205d9e / #c2e6ff dark) collide with a select option called "blue", while the neutral gray (#f0f0f0 / #cecece / #202020 light, #222222 / #484848 / #eeeeee dark) cannot. The "+N" badge uses the neutral gray.

**Record picker.** Sources: Teable's All and Selected tabs, search and footer create button with a pre-filled reciprocal link ([EditorMain.tsx](https://raw.githubusercontent.com/teableio/teable/develop/packages/sdk/src/components/editor/link/EditorMain.tsx)); NocoDB's preview and "View all in table" ([NocoDB docs](https://nocodb.com/docs/product-docs/fields/field-types/links-based/links)); Baserow's ten-row paging ([Baserow docs](https://baserow.io/user-docs/link-to-table-field)). Recommended: a 320 to 480px popover with auto-focused search (debounce 300 to 400ms, server-side), a virtualised list, an "All / Linked" toggle, multi-select that stays open, a pinned "+ New record" that links the new row and its reciprocal, and a bulk cap of 1,000. When the relationship is one-to-one or one-to-many, "All" hides records already used elsewhere (Teable semantics). The unmounted `LinkedRecordPicker.tsx` already has create logic ([parity audit](database-field-parity.md)). A two-line row (primary text, muted secondary field) is a design suggestion. A chip click opens the record only when the cell is active, and degrades to plain text without access (Baserow).

**Relationship wording.** Airtable asks no cardinality question; Teable derives four types from two toggles; Attio and NocoDB name the type with a one-line definition ([Teable](https://help.teable.ai/en/basic/field/link), [Attio](https://attio.com/help/reference/managing-your-data/attributes/relationship-attributes)). Recommended wording, assembled from these: two questions, "Can one Project link to many Tasks?" and "Can one Task link to many Projects?", each answered "Yes, many" or "No, only one". Below them a read-only summary states the result in words ("One Project has many Tasks") with the short label (1:N). A toggle reads "Also add a field in Tasks that links back", on by default, with a name pre-filled from the other table (plural when many) and editable; self-links ask for two names (Notion's Next task and Previous task) ([Notion](https://www.notion.com/help/relations-and-rollups)). The parity audit shows KDOps always creates the reciprocal field named after the source table, so the toggle and name are new behaviour, for new links only. Airtable's single-record setting is a soft, picker-only rule; a true one-to-one guarantee needs a unique constraint, which is a database change.

**Relationship view.** Supabase Studio's schema visualiser uses React Flow with dagre, one schema at a time, positions saved in localStorage and PNG or SVG export; NocoDB's ERD lets you drag tables but does not save the layout ([Supabase source mirror](https://graphtechnologydevelopers.github.io/supabase/fn-schemagraph-tsx-schemagraph.html), [NocoDB table details](https://nocodb.com/docs/product-docs/table-details)). `@xyflow/react` is about 56.6 KB gzipped (an aggregator figure, approximate), and React Flow's own layout guide lists dagre as the default and elkjs, at roughly 1.4 million by its badge (unit unstated), as rarely recommended ([depscope](https://depscope.dev/pkg/npm/@xyflow/react), [React Flow layouting](https://reactflow.dev/learn/layouting/layouting)). Recommended: nodes list only the primary field and link fields; edges carry "1" and "N" labels (clearer than crow's foot for non-technical readers); clicking an edge opens that link field's settings; lazy-load the route. localStorage positions cost nothing; shared positions need a table. With only a handful of tables, a hand-laid SVG without a dependency may suffice (inference).

## Rollup setup is three ordered selects, a function menu and a preview

**Setup order.** Airtable, Baserow, NocoDB, Teable and Notion all use a single dialog with link field, then target field, then function, and no wizard ([Airtable rollup](https://support.airtable.com/docs/rollup-field-overview), [Baserow rollup](https://baserow.io/user-docs/rollup-field), [Notion](https://www.notion.com/help/relations-and-rollups)). NocoDB disables its Formatting tab until a target is chosen ([NocoDB lookup](https://nocodb.com/docs/product-docs/fields/field-types/links-based/lookup)). Recommended dialog: Name; Link field; Target field (type icon per field); Function; optional "Only include linked records that meet conditions" (the same filter builder as views); Format; Preview; "Create field". Each select is disabled until the previous one is set. Count shows only the link select, and lookup hides Function. The empty state is where KDOps can beat every researched product: Airtable says "No available sources to count. Add a count source, then try to configure your count again" and sends the user away, and Baserow shows nothing ([Airtable count](https://support.airtable.com/docs/count-field-overview)). Show "This table has no link field yet" with a "Create a link field" button that opens the link dialog and returns with it selected.

**Function menu.** Notion groups calculations as general, number-only and date-only, and NocoDB hides functions that do not fit (a date field gets no Sum) ([NocoDB rollup](https://nocodb.com/docs/product-docs/fields/field-types/links-based/rollup)). No competitor was found with a plain description per item; these are drafted here for the 15 functions in `computations.ts`: Sum "Adds up the numbers", Average "The mean of the numbers", Median "The middle number", Min and Max "Smallest" and "Largest" (shown as "Earliest" and "Latest" for dates), Count "Counts linked records that hold a number", Count values "Counts linked records that are not empty", Count all "Counts every linked record, empty or not", And, Or, Xor "All checked", "Any checked", "An odd number checked", Join "Joins text with a separator you choose", Unique "Each distinct value once", Compact "Drops empty values". Today COUNT counts linked records, not numbers, so that label must wait for the parity fix. Group the menu Any, Number, Date, Checkbox via a pure `functionsForType(type)`.

**Empty results and errors.** Use NocoDB's documented rule: counts and sums show 0 when nothing is linked, while min, max and averages stay empty. For a broken configuration (deleted or retyped source), show an explicit error token with the reason on hover; NocoDB shows `ERR!` while Airtable blanks every cell, and the token is easier to diagnose.

**Preview.** No researched relational dialog shows a computed sample; Attio's formula composer previews a value and is the nearest ([Attio](https://attio.com/help/reference/managing-your-data/attributes/formula-attribute-examples)). Recommended: show the first three to five rows of the current table (primary field, then result), with "0" or empty where there are no links, run through the same formatter as the grid. This needs linked rows for only those few records, which batching makes cheap.

**Result formatting.** Notion keeps number format and decimal places in the same popover as the calculation; NocoDB's Formatting tab offers Decimal, Currency, Percent for numbers and Date, DateTime or Time for dates, applied in the grid, expanded record and exports ([NocoDB lookup](https://nocodb.com/docs/product-docs/fields/field-types/links-based/lookup)). Recommended: after the function is chosen, derive the result type (Sum of currency stays currency; Min or Max of a date stays a date; counts are integers), prefill the Format row from the source field, and reuse `NumberFormatPanel` with the preview strip. If the target field's type changes, revert the result to a plain number as NocoDB does. A lookup renders by source type (select pills, formatted dates and numbers) instead of joined text. Computed cells follow `database-field-design-research.md` (read-only tint, `fx` header glyph, `aria-readonly`, right-aligned tabular numbers).

**Where to compute.** Three models appear: persist and recompute on dependency change (Baserow; Teable likely), compute in SQL at read time (NocoDB), and per cell in the client, which is KDOps today and was found in none of the studied products ([NocoDB genRollupSelectv2](https://raw.githubusercontent.com/nocodb/nocodb/develop/packages/nocodb/src/db/genRollupSelectv2.ts), [Teable rollup](https://help.teable.ai/en/basic/field/rollup)). Only the first two allow sort, filter, group and footer totals over all rows. NocoDB skips sorting some virtual columns, and Baserow has reported stale lookups. For Supabase, a SQL subquery per rollup is the simplest correct model and a trigger-maintained column the read-heavy alternative (inference; `docs/database-structure-spec.md` section 3 holds the existing design).

## The settings panel groups Format, Rules, Default and Advanced

**Structure.** The verified products use one short panel (name, optional description, type, type-specific settings) and keep rare options behind a control; NocoDB makes "Add Description" a button, and Attio separates Required and Unique into their own group ([Attio help](https://attio.com/help/reference/managing-your-data/attributes/create-manage-attributes), [NocoDB fields](https://nocodb.com/docs/product-docs/fields), [Baserow adding a field](https://baserow.io/user-docs/adding-a-field)). NN/g advises frequent options first, advanced options behind a labelled control, and no more than two levels ([NN/g](https://www.nngroup.com/articles/progressive-disclosure/)). Airtable is the only product confirmed to show a preview of the formatted value at the bottom of the configuration window ([Airtable number fields](https://support.airtable.com/docs/number-based-fields-in-airtable)). No source shows a right-hand preview pane, so the one-line strip is the verified pattern.

**Recommended layout.** Single column, 480 to 560px wide, 85vh maximum with a scrolling body and fixed header and footer. Order: Field name with an "Add description" text button that expands a two-line box; a Type button showing icon and name that opens a searchable, categorised list; Format (type-specific, with a segmented control for decimals 0, 1, 2, 3+ and the preview strip "Preview ₦1,234.50" via the real formatter); Rules; Default; a collapsed Advanced section containing uniqueness and a text-danger "Delete field". The footer is sticky with "Cancel" and "Save field", enabled only when something changed. `NumberFormatPanel`, `FieldValidationPanel` and `FieldDefaultPanel` already exist, so this is regrouping.

**Rules block.** "Required" becomes a switch row with the helper "A record can't be saved while this is empty." The range is one group, "Allowed range", with "Smallest" and "Largest" inputs side by side, placeholders "No minimum" and "No maximum", unit adornments inside the inputs, and one shared error line. Default shows "No default" as its empty state with an inline clear, and the helper "Used when a new record is created. Existing records aren't changed." NocoDB documents new-records-only defaults and forbids default plus unique ([NocoDB fields](https://nocodb.com/docs/product-docs/fields)); Baserow warns under Default when something overrides it. Error wording follows GOV.UK and NN/g: state what is wrong and how to fix it, show it next to the field after the user finishes typing, add an icon, and avoid "invalid" ([GOV.UK](https://design-system.service.gov.uk/components/error-message/), [NN/g](https://www.nngroup.com/articles/errors-forms-design-guidelines/)). Messages (drafted here): "Smallest value must be the same as or lower than the largest value." and "Default must be between 0 and 100." Airtable has no min or max for these fields and no source shows a paired range control, so the pairing is original.

**Tokens and accessibility.** Map these recommendations onto the app's existing tokens rather than adding hex to components; they are not sourced from any product. Light and dark: text #111827 / #F3F4F6, label #374151 / #D1D5DB, helper #6B7280 / #9CA3AF, border #D1D5DB / #374151, subtle surface #F9FAFB / #111827, error #B42318 / #F97066, focus ring 2px accent with 2px offset. Spacing on a 4px base: label to control 6 to 8px, field to field 16px, group to group 24 to 32px with a 1px divider. Type: title 16 to 18px / 600, section heading 12px / 600 muted, label 13 to 14px / 500, helper 12px, input 14px at 36 to 40px high, switch rows at least 44px. Motion: 150 to 200ms, within `prefers-reduced-motion`. Per the WAI-ARIA dialog pattern, the dialog needs a visible title as its accessible name, Tab trapped inside, Esc to close and focus returned to the opener ([W3C APG](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)). Wrap the range pair in a `fieldset` with a legend, set `aria-invalid` and `aria-describedby` to the shared error, and keep the preview non-live and labelled ("Preview: ₦1,234.50"). Per the repository rules, nothing here writes on mount or render; saving happens only on "Save field" with a changed value.

## Decisions the owner must make

| Decision | Options | Recommendation |
|---|---|---|
| Field references as pills or coloured text | Pills (Notion, Coda) or coloured text (Airtable) | Pills behind a flag with a plain-text toggle; if IME testing fails, ship coloured text |
| Pill and chip colour | Radix blue, neutral gray, or purple for formula pills only | Neutral link chips so they differ from coloured select options; purple formula pills as in Airtable's field colour |
| Compute rollups on the server | Client per cell, SQL at read, or stored column | Keep the client with batching now; plan SQL at read for sort, filter and group (item 14) |
| Relationship diagram dependency | React Flow plus dagre (about 57 KB gz plus dagre), hand-laid SVG, or none | Decide after counting tables; lazy-load React Flow if there are more than about ten |
| Save with formula errors | Block on any error, block on parse errors only, or never block | Block on parse errors only; warn on unknown fields |
| Rename strategy | Rewrite text now, ids later | Rewrite now, atomically if an RPC is acceptable |
| Required on existing empty rows | Enforce only at record creation or also at edit | Creation and edit, but never rewrite existing rows |
| AI "describe it" box in the formula editor | Add or skip | Skip for now; every researched product keeps it secondary |
| Count-only display for link cells | Option or none | Optional display style for fields with 100 or more links |

## What is not verified

The bundle sizes were measured by the researcher with esbuild and gzip -9 and are not independently confirmed; bundlephobia returned 429 and bundlejs 404, so re-measure with the app's Vite build. The Notion token claims come from third-party guides (Thomas Frank), and whether Notion or Coda store ids or names is unverified. Airtable's lack of an overflow indicator comes from user complaints. The React Flow and dagre sizes come from an aggregator and a docs badge with an unstated unit. Several competitor claims rest on search summaries of community threads. No source gave hex values, pill or chip sizes, popup sizes or fonts for Airtable, Notion or Coda; the syntax colours, settings tokens and most dimensions above are recommendations, and contrast was not computed for them. Not tested: CodeMirror IME behaviour with pills on Android and Safari, and screen-reader output for replaced widgets (NVDA, VoiceOver); the researcher's CodeMirror code sketch was not compiled. Not researched: Coda, Grist and Retool relationship setup, Supabase's foreign-key dialog, Stripe, Vercel and Linear settings forms, Excel's live "Formula result" dialog. Not verified for KDOps: the link renderer's badge logic, whether existing queries support picker search, and what in `FormulaEditor.tsx` can be reused; the parity audit was code-read only.

## Conclusion

The research shows that the four complaints share a cause: each feature has the data it needs but no shared presentation layer. The tokenizer, the function list, the formatter and the chip-fit calculation can all be pure functions, written and tested first, and then reused by completion, hints, lint, preview, cells and dialogs. That ordering also contains the risk, because the one genuinely uncertain piece, pills under mobile IME, sits last in the sequence and can fall back to coloured text without redoing anything else.

Two opportunities are open that no researched product fills: a sample-row preview in the rollup dialog and a visible "+N" in link cells. Rollups stay display-only without server computation; if sorting, grouping or filtering them matters, item 14 is the largest on the list and belongs before the diagram.
